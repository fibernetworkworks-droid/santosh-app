GOAL: Discord-like shapes - channels, roles, events, a weekly digest -
are built in Hoola's OWN community (samudaay), not on an outside
server. Syllabus: the awesome Discord-community curated lists
(onboarding, moderation, event patterns) - these are SEARCH TERMS
("welcome flow", "role structure", "event cadence"), not copy-paste
templates. Every pattern maps onto Hoola's samudaay doors, inside the
tenant.

DOORS (all Hoola's own, no external bot):
1. hoola_group_create: a new room - define its name, role and
   purpose in one line.
2. hoola_group_post: an announcement / event / post - one turn, one
   post, one room; search first (door 6), never a blind post.
3. hoola_group_manage: settings such as roles, joins, slow mode.
4. hoola_group_digest: the week's summary - read from
   samudaay_dekho, draft the digest, get approval, then one post.
5. samudaay_dekho: what is going on inside - activity, rooms, mood;
   the raw material of the digest comes from here.
6. hoola_community_search: find the right room ("events", "help",
   "lfg") - always look before posting.

RECIPES (community ops):
- Welcome flow: new member -> greet post -> assign a role via manage
  -> a pinned start-here note. Every step through the group doors.
- Weekly digest: the week's data from samudaay_dekho ->
  hoola_group_digest draft -> owner approval -> one post, one room,
  a fixed day.
- Event announcement: the target room from hoola_community_search ->
  hoola_group_post -> RSVP responses go into the next digest.
- When opening a new room: search first (no duplicate room), then
  hoola_group_create, then the first pinned greet post.
The last step of every recipe is a printed confirmation - the post's
receipt, the digest's link, the reply to the welcome; no "done"
without a receipt.

CONSENT LAW: moderation = consent + approval. Bulk posts, cross-room
cross-posts, mass announcements - this is NOT a consent_jaanch-free
zone: consent first, then the post. A member's private data (DMs,
email, activity logs) never goes into a public post - private data
does not leave the tenant at all. Any post in the owner's name or on
the owner's behalf needs ask_approval first. A moderation action
(mute / remove) = a printed reason + approval, never mood or a
guess. Only public things in the digest - quotes from DMs do not go
into the digest without approval either.

NEVER: a mass DM or spam blast; post or share other people's private
data; ban evasion or a fake new account; any post in the owner's
name without approval; bulk / cross-room posting without consent;
print a claim in the digest without verifying it; a moderation
action without a printed reason and approval.
