GOAL: the first job of the morning - turn the inbox and the tasks into
ONE firm queue, so the day starts with decisions, not with searching.
Syllabus: the lists/inbox-zero/kanban patterns of awesome-productivity
(generic reference) - but the doors are Hoola's real tools. This starter
runs TOGETHER with the morning-briefing skill: the briefing gives the
BRIEF (what happened, what is pending - looking); this gives the TRIAGE
(a DECISION on each item - now/later/someone else/no). Read the brief
first, then run the triage - looking is one thing, deciding another.
One list, one place, one truth - nothing less.

MORNING QUEUE (one slot, a fixed time - once in the morning, not all
day):
1. email_triage: put every mail in a bucket - NOW (answer this
   moment), LATER (carried forward with a written date), DELEGATE (to
   the right person, after approval), NEVER-DELETE-SNOOZE (nothing is
   deleted; noise is snoozed/archived). Each mail gets exactly one
   bucket - do not think twice, keep the first decision.
2. email_rule: for a pattern that keeps showing up (newsletters,
   notifications), make a rule - next time that mail will not even
   reach the triage; a rule is a one-time effort, a saving every
   morning.
3. email_snooze: mails for later go out of the day - out of the
   calendar, out of the head. If a snooze date is written, that is the
   firm date.
4. email_follow_up: for those whose reply is awaited, put them on the
   follow-up list - things that should come back are not lost. With
   each follow-up write what needs to be reminded.
5. kaam_plan + kaam_status: pull the current work and the status of
   running tasks, MERGE them with the new tasks that came from email -
   into ONE list. Add with list_add, close with list_done, view the
   whole day with list_show. Two places are two truths. While merging,
   catch duplicates - if the same task is in both email and tasks, keep
   one and note the source.

RULES: with every item, one line of NEXT ACTION - like "Send Ravi the
quote by 4 pm"; not a 3-line essay. The order is fixed: first the email
buckets, then rules/snooze/follow-up, then the task merge - in one pass,
do not loop again. Anything that goes to a delegate or in the owner's
name = ask_approval first. The record of each bucket move is in printed
output - evidence is the truth, not memory. When the queue is ready,
show it to the owner - as a report, without sending anything; if
something must be sent, ask_approval first.

NEVER: delete a mail (snooze/archive only - never delete); an auto-reply
in the owner's name without ask_approval; list_done without evidence (no
"done" without seeing the output); 5 actions in one item (write only the
one action that moves it forward); turn the triage into an all-day
activity - one slot, fixed; private data outside the tenant.
